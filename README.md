# 国外小博主寻找器

一个本地桌面软件：按平台、领域、数量，抓取 **5,000–20,000 粉丝**的国外创作者，自动跳过历史已出现过的账号，并导出 Markdown / CSV。每个平台内部串行，平台之间默认并行。

> 想看完整的启动链路、限速模型、数据落盘时机和排障对照，见 **[工作方式.md](工作方式.md)**。
> 这轮“更安全 / 更快 / 更多 / 更准”的调研、实测数字和取舍，见 **[优化方案.md](优化方案.md)**。

## 快速开始

双击 **`启动.vbs`**（或 `launch.vbs`）。

软件会打开一个独立窗口，不需要安装 Node、不需要联网安装依赖。Electron 运行时已经放在 `runtime/electron/` 里。

如果双击没反应：

1. 确认 `runtime/electron/electron.exe` 存在；
2. 尝试双击 `启动.bat` 看是否有报错；
3. 如果刚复制完文件，等几秒再试（Windows Defender 可能短暂锁定新写入的 exe）。

## 能做什么

- **平台多选**：YouTube、X / Twitter、Twitch、Kick、Rumble、TikTok 六个平台已接入；TikTok 通过公开搜索结果 + 主页 embed 页读取粉丝数和最近视频时间，不需要登录。
- **领域多选**：25 个垂类，包括新闻 / 时政、木工、修复、美食、烘焙、摄影、陶艺、绘画、独立游戏、复古游戏、动画、音乐、语言、旅行、户外、健身、科技、历史、棋类、编织、模型、宠物、汽车、园艺、DIY。
- **数量可选**：目标 1–200 个，默认 30 个。
- **平台进度**：顶部会显示每个平台当前在跑的关键词、限速等待、出错或完成状态，以及该平台已找到的数量。
- **结果筛选**：结果区可以按平台切换、按名称/简介搜索，并按「最近活跃」或「粉丝最多」排序；结果表左侧头像使用各网站标志（YouTube / X / Twitch / Kick / Rumble / TikTok），鼠标悬停显示来源平台。
- **实时日志**：日志面板可以收起，运行中会实时显示搜索、限速、跳过和错误信息。
- **快捷键**：`Ctrl + Enter` 开始寻找，`Esc` 停止当前运行。
- **自动去重**：所有出现过的 YouTube 频道 ID、X handle、Twitch login、Kick / Rumble slug、TikTok handle 都会记入 `data/seen.json`，下次自动跳过；也可以一键清空历史库。
- **历史记录**：每找到一个创作者就写入 `data/history.json`，按**首次发现日期**归档；同一平台同一 ID 只记一次，之后再遇到只更新「最近见到 / 次数」，不会每天重复。顶部「历史记录」按钮可以按天折叠查看（点日期展开/收起，最新一天默认展开；搜索或平台筛选会自动展开命中的日期）、搜索名称/handle、按平台筛选；**头像使用各网站标志（YouTube / X / Twitch / Kick / Rumble / TikTok），每天内先按平台归类排列；重复找到的账号（含同一天同一平台的同名账号）排在每天最下面，并用「重复 N 次」标出次数**。升级后会自动把 `results/` 里的旧结果补进历史。
- **活跃度筛选**：默认只保留最近 90 天有更新的创作者，可以精确到天（0 = 不限）。YouTube 会逐个打开频道 `/videos` 页，读取最近一条长视频的时间；Twitch 读取最近开播时间；X 从公开主页的最近推文时间读取；Kick 读取最近开播 / 最近视频时间；Rumble 读取频道页最新视频时间。X 没有公开推文时间时显示 `—`，但仍保留；Kick / Rumble 查不到活跃时间时按“无法确认”跳过。
- **新闻类**：领域列表第一项是「新闻 / 时政」，建议把「最近活跃（天）」设为 7–30 天，优先抓日更 / 周更的小型新闻频道。新闻和美食两个领域已内置一批地区 / 菜系长尾词（非洲、亚洲、中东、巴尔干、南中国海、意大利、墨西哥、印度、泰国……），比只搜 `geopolitics analysis` 这种大词更容易捞到 5k–20k 的小频道。
- **品牌过滤**：默认排除名称/简介里带 official、shop、store、supply、magazine、community、agency、media 等字样的机构号。
- **导出**：结果表可以导出 Markdown 和 CSV；运行中每找到一批结果就会增量写入 `results/` 下的 JSON + Markdown + CSV（约 1.5 秒合并一次），结束后再写最终版。

## IP 安全（重点）

每个平台内部严格串行：同一时刻每个平台只发一个请求，**请求间隔从上一次请求结束起算**（慢请求、超时之后也不会贴脸连发）。默认开启「平台间并行」，但并行只发生在不同站点之间：**同一个域名在全局仍然只允许一个请求在飞**，Brave / DDG 之间还额外强制 2 秒间隔——X / Rumble / TikTok / Kick 不会同时去打同一个搜索源。关闭「平台间并行」后所有平台排队执行，回到完全单线程。一次运行中，每个领域的每个关键词只会搜索一次，不会重复浪费请求。

请求本身走 Electron 自带的 **Chromium 网络栈**（真实浏览器 TLS/HTTP2 指纹、连接复用、Cookie 会话），不是 curl 的指纹；遇到 **429/503 会全局退避**（优先按 `Retry-After`，否则 30→60→120 秒，上限 5 分钟），所有平台一起停下来，而不是各自重试。

默认参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| 请求间隔 | 5 秒 | 上一次请求**结束**到下一次开始的间隔，最低强制 3 秒 |
| 随机抖动 | 1.5 秒 | 在基础间隔上再加 0–1.5 秒随机量 |
| 每 N 次长休 | 8 次 | 每发 8 个请求后额外休息 |
| 长休时长 | 20 秒 | 长休的实际时长 |
| 代理 | `http://127.0.0.1:7897` | 留空则直连 |
| 平台间并行 | 开启 | 每个平台内部仍串行；关闭后所有平台排队 |
| 单次请求上限 | 320 次 | 达到后安全停止，可在「高级限制」里改 |
| 时间上限 | 30 分钟 | 达到后安全停止，可在「高级限制」里改 |

界面右上角有「快速模式 / 安全模式」两个预设：

- **快速模式**：3 秒间隔、0.5 秒抖动、每 20 次长休 10 秒。仍然每个平台内部严格串行，只是把等待压到最低，适合先跑一轮看看。
- **安全模式**：6 秒间隔、2 秒抖动、每 6 次长休 30 秒。

如果还是担心，可以把间隔调到 8–10 秒。

**不要**同时开多个软件实例；平台间并行由软件内部统一调度。如果特别担心 IP，可以在「IP 安全」里关闭平台间并行，回到完全单线程。

## 六个平台的抓取方式

> 所有平台请求走 **Electron 自带的 Chromium 网络栈**（真实浏览器 TLS/HTTP2 指纹、连接复用、Cookie 会话），只有 DDG / Brave 搜索源和 TikTok embed 走 curl——这是实测后按站点分开的，不是一刀切。详细数字见 [优化方案.md](优化方案.md)。

- **YouTube**：直接调 `youtubei/v1/search` 的 JSON 接口（`POST`，约 17KB / 20 个频道），不再打开 257KB 的整页 HTML；接口不需要 API key，异常时自动回退整页解析。第一页的“区间内且未见过”候选不足 4 个时自动翻第二页（同样是 17KB / 20 个）。活跃度优先读频道 RSS（`feeds/videos.xml`，约 27KB），RSS 不可用才回退到 `/videos` 整页（约 1.3MB）。粉丝数是频道卡片展示的四舍五入值（如 12.4K）。
- **X / Twitter**：先用 Brave 搜索 `site:x.com <领域关键词>` 发现公开主页，再用 DDG 兜底（DDG html 返回 200 但解析不出结果时，会用更轻的 `lite.duckduckgo.com` 再试一次）；然后逐个打开 `x.com/<handle>` 公开主页。**X 对 curl 会返回不含粉丝数的降级页面，只有浏览器指纹才给完整数据**，所以核验必须走 Chromium：从页面解析 `9,081 Followers` 精确值、`Joined` 和最近推文时间，姓名取 `og:title`。DDG 结果摘要里带 `Followers` 时，会在打开主页前跳过**明显**不在区间里的账号（低于下限一半或高于上限 2 倍）；临界值仍以主页为准。**Brave / DDG 的冷却状态与 Rumble、TikTok、Kick 共享**：谁先撞到 429/202，其余平台本轮就不再重复请求搜索源。
- **Twitch**：调用 Twitch 公开 GraphQL 接口，直接拿到频道名、简介、粉丝数和最近开播时间，不需要登录。
- **Kick**：先调用 Kick 公开搜索接口 `/api/search?searched_word=<关键词>`，拿不到结果时再用 Brave / DDG 搜 `site:kick.com <关键词>`；随后读公开接口 `/api/v2/channels/<slug>` 拿粉丝数和简介；活跃度看是否正在直播，否则读 `/videos` 的最近发布时间。搜索源的冷却与 X / Rumble / TikTok 共享。
- **Rumble**：先用 Brave / DDG 搜索 `site:rumble.com <关键词>` 发现频道，再打开 `rumble.com/c/<slug>`（404 时回退到 `rumble.com/user/<slug>`）解析粉丝数、简介和页面里最新的 `<time>`；DDG 摘要带 `/c/` 或 `/user/` 路径时会直接走命中的路径，少一次 404 请求；摘要里的粉丝数只用来跳过明显区间外的账号。新闻 / 时政类还会额外读取 `rumble.com/channels/news` 的频道列表，避免只靠搜索引擎时候选太少。正在直播或刚直播过的频道会标成“正在直播 / DVR”。
- **TikTok**：先查 DDG 的 `site:tiktok.com <关键词>`，结果不足 4 个不同候选时再用 Brave 补充，合并去重得到 `@handle`；DDG 结果块里的 `353.8K Followers` 会先用来跳过**明显**不在区间里的账号（低于下限一半或高于上限 2 倍），临界值仍打开 `tiktok.com/embed/@<handle>` 以主页为准。embed 页固定走 curl（同样的请求 Chromium 会被回 429），解析精确 `followerCount`、`nickname`、`signature` 和 `videoList`。最近活跃时间从视频 ID 的高 32 位（Unix 秒）还原，取 videoList 里最新的一条；私密账号跳过，embed 解析失败时回退到普通主页只补粉丝数和简介。DDG 一次能给出 4 个以上候选时不再额外请求 Brave。
- **TikTok 说明**：不需要登录、不调用签名接口；搜索页本身是 JS 渲染，所以发现依赖公开搜索引擎结果（DDG 优先，Brave 兜底），冷门领域的候选数量会比 YouTube 少。成功的发现结果会缓存 12 小时，冷却期间重跑仍能用上次的候选。DDG 返回 202 或 Brave 返回 429/403 都算被限流，两个源都会各自冷却 10 分钟；**两个都在冷却时，本次运行直接跳过 TikTok（日志只报一次，平台卡显示「冷却」），不再对每个关键词重复撞墙；冷却状态与 X / Rumble 共享**。

## 数据位置

```
creator-finder/
  data/seen.json          # 去重库（可清空）
  data/history.json       # 按天归档的收录历史（首次发现日期 + 最近见到 + 次数）
  data/cache.json         # 最近 12 小时的核验缓存（清空历史库时一起清）
  data/keyword-cursor.json # 关键词轮换位置（每个平台+领域一个游标）
  data/logs/2026-11-01.log # 每次运行的完整日志（按天一个文件，出问题时看这里）
  results/                # 每次运行的 JSON / Markdown / CSV
  src/domains.js          # 领域和关键词
  src/platforms/          # 六个平台的适配器
  public/                 # 界面
  runtime/electron/       # 自带 Electron 运行时
```

## 增加领域或关键词

编辑 `src/domains.js`，照着现有格式加一项：

```js
{
  id: 'my-domain',
  name: '我的领域',
  queries: {
    youtube: ['long tail query 1', 'long tail query 2'],
    x: ['short query'],
    twitch: ['short query']
  }
}
```

YouTube 关键词建议用长尾词（越具体越容易搜到小频道）；X/Twitch 用短词即可。一次运行里每个关键词最多搜两页。

**关键词会自动轮换**：每个平台 + 领域记一个游标（`data/keyword-cursor.json`），这次从第 10 个词开始，下次就从第 11 个词继续，不会每天都从同一批词开始、搜回来的人全在「已见」里。清空历史库会把游标一起归零。

**新闻 / 时政的词表已经按地区 + 议题细分到 70 多个词**（`src/domains.js` 里带实测产出注释，例如 `bolivia politics` 8 个、`taiwan politics` 7 个、`election analysis` 7 个）。加词时照这个做法：先跑一遍 `_probe_keywords.cjs` 看这个词能出几个 5k–20k 的新频道，再把高产的放前面、通用大词放最后。

Kick / Rumble 没有单独写关键词时会复用 Twitch 的关键词；TikTok 会先找自己的 `tiktok` 数组，没有就复用 Twitch 的短词。想单独控制可以在 `queries` 里加 `kick`、`rumble`、`tiktok` 数组。

## 常见问题

**Q：目标 30 个，为什么只找到 10 个就结束了？**

A：目标数是上限，不是保证。软件对选中领域的每个关键词最多搜两页；所有平台都显示"完成"或"无新候选"就说明关键词已经跑完（或提前判定抓空），不是软件中途停了。常见原因：① 历史库默认跳过已出现的账号；② 5k–20k 粉丝 + 最近活跃两个条件卡掉了大部分候选（实测新闻类关键词的 40 个搜索结果里经常有 35+ 个是 2 万粉以上的大号）；③ 某平台搜索源在冷却（会标"冷却"）。想找到更多：多选几个领域、换更细的关键词、把「最近活跃」调大；清空历史库只会把旧账号找回来，不会出现新账号。

**Q：为什么这么慢？能不能再快？**

A：慢的部分主要是「防止同一平台连续请求」的间隔，不是网络。软件已经在不并发的条件下做了三件事：YouTube 活跃检查改读 27KB 的 RSS、TikTok / X / Rumble 先用搜索摘要的粉丝数把区间外的人筛掉、同一个账号 12 小时内再次核验直接命中缓存。想更快可以点「快速模式」（3 秒间隔），或把「最近活跃」改成 0 跳过活跃检查。再快就只能同一平台并发请求，那会违反你定的防封规则，不建议。

**Q：历史记录会不会每天重复？**

A：不会。历史按「平台 + 账号 ID」去重，每个账号只出现在**首次发现的那一天**；以后再搜到只更新「最近见到 / 见过次数」，不会新增一条。清空历史会同时清掉去重库和核验缓存，下次会重新找到旧账号；`results/` 里的运行文件不会被删除。

**Q：为什么有时候一个都没找到？**
A：现在日志会直接写出原因，不用猜。典型的一句是：

```
YouTube 汇总：跑了 11 个关键词，候选 440，无粉丝数 38，区间外 373，已见 24，机构 2，停更 3，新增 0
本轮 0 个：候选 440，无粉丝数 38，区间外 373，已见 24，机构 2，停更 3。这些关键词的搜索结果被大号占满（粉丝数超过上限），换更具体的小众关键词或换领域更容易出结果
```

看第二行就能判断该怎么做：
- **区间外占绝大多数** → 这个词的搜索结果都是大号，换更细的长尾关键词或换领域；
- **已见占多数** → 这些人在前面的运行里已经给过你，换领域或明天再跑（去重库会一直挡住重复的人）；
- **停更占多数** → 把「最近活跃（天）」调大，或换领域。

另外，同一个平台的**连续 4 个关键词都没有「区间内且未见过」的候选时，会提前收工**（平台卡显示「无新候选」），不会再把剩下的词一个个空跑一遍。

**Q：为什么点「开始」后一分钟就结束了，平台卡写「无新候选」？**
A：这是提前收工，不是出错。它表示这个领域的搜索结果已经被大号占满、或者候选都已在「已见」里，继续跑剩下的关键词也只是重复同样的事。日志里会写「连续 N 个关键词都没有…剩下 M 个词不再空跑」。想继续找：换领域、换更细的关键词，或清空「已见」再跑（清空会让你再次看到已经给过的人）。

**Q：X 一个都找不到？**
A：分两步看。**核验已经修好**：X 以前对 curl 返回不含粉丝数的降级页面，现在核验走 Chromium 浏览器栈，实测历史里 8 个有效 X 账号 8/8 都能解析出精确粉丝数、姓名和最近推文时间。**发现仍然依赖 Brave / DuckDuckGo 的公开搜索结果**：被限流时软件会自动冷却 10 分钟并切到另一个搜索源；如果两个都不可用，X 本轮就会被跳过。这个冷却在 X / Rumble / TikTok / Kick 之间是共享的，一个平台撞到限流，其余平台本轮不会各撞一遍。想马上恢复：等 10–15 分钟，或在「IP 安全」里换一个代理出口。

**Q：TikTok 一直提示「DDG / Brave 冷却中」？**
A：这是搜索引擎在限这个 IP，不是软件出错。DDG 会返回人机验证页（HTTP 202），Brave 返回 429，两家各自冷却 10 分钟；这段时间里 TikTok 的候选来源就断了。YouTube / Twitch / Kick 走的是各自的官方接口，不受影响。软件现在的处理是：撞到一次就整轮跳过 TikTok、日志只写一条、平台卡标「冷却」，不会每个关键词都重试；如果 12 小时内成功发现过，会直接用缓存里的候选。想马上恢复可以等 10–15 分钟，或在「IP 安全」里换一个代理出口（换节点就等于换 IP）。

**Q：YouTube 提示“页面结构变化”？**
A：YouTube 偶尔会返回不含 `ytInitialData` 的页面，软件会自动重试一次；如果持续出现，说明页面结构改了，需要更新 `src/platforms/youtube.js` 的解析逻辑。

**Q：粉丝数准不准？**
A：YouTube 是频道卡片展示的四舍五入值（如 12.4K）；Twitch、Kick 是接口返回的精确值；**X 是浏览器页面上的精确值（如 9,081）**；Rumble 是频道页展示的 `12.4K Followers`；TikTok 是 embed 页的精确 `followerCount`。筛选区间以这些展示值为准。X 的精确值依赖 Chromium 页面，curl 拿到的页面不含粉丝数——所以不要用命令行 curl 去验证 X 的解析结果。

**Q：会不会封 IP？**
A：每个平台内部是低频串行请求，默认 5 秒一次、每 8 次长休 20 秒；平台之间默认并行。但任何抓取都不能 100% 保证不被限流。建议保持默认或更慢；担心的话关闭平台间并行，不要短时间内反复重跑同一领域。

## 发现通道：搜索引擎靠不住之后

2026-11 在国内代理出口上实测：

| 源 | 结果 |
|---|---|
| DuckDuckGo（html / lite / vqd 流程 / d.js） | 一律 202 人机验证 |
| Brave 网页 | 浏览器指纹 429；curl 能 200，但会给 30–60 秒慢速陷阱，很快也 429 |
| Bing（含 ensearch / mkt） | 200 但**忽略 site:**，返回的是泛词结果 |
| Google / Yandex / Mojeek / Startpage / Ecosia / Qwant / Yep / Yahoo / Ask | JS 壳 / 验证码 / 403 / 500 |
| Rumble 原生搜索 /search/video、/api/v1/search | 403 或壳页面 |
| TikTok 搜索页 / 话题页 | JS 渲染，HTML 里没有账号 |

所以 X / TikTok / Rumble 的「发现」现在按这个顺序取候选：

1. **Brave Search API**（可选）：设置里填 key 后直接走 JSON 接口，不受 IP 限流影响。
2. **跨平台桥接**（默认开启，不依赖任何搜索引擎）：Kick 频道接口里的 user.twitter / user.tiktok / user.youtube、YouTube 视频简介与频道「关于」页里创作者自己填的外链 → 其它平台候选。
3. **只勾 X / TikTok / Rumble 时**：先用 YouTube 当发现引擎采一批种子（最多 12 个频道），不产出 YouTube 结果。
4. **网页搜索兜底**：DDG 优先（15 秒上限），Brave 走 curl 且识别慢速陷阱。
5. **备用出口**：填了多个代理时，搜索源返 429/202/403 会自动换出口并清空旧退避（15 秒内不连切两次）。

搜索源被限流时不再把平台标成「出错」：日志写「暂时不可用，本轮先跳过这个关键词」，平台继续跑别的词，也不计入 failedPlatforms。

## 应用内升级

顶部「检查更新」：

1. **检查**：读 api.github.com/repos/meiyoume/creator-finder-release/releases/latest；不可达时回退 jsDelivr 上的 latest.json 快照。版本号以 package.json 为准（app.getVersion() 在主进程外会返回 Electron 自己的版本）。
2. **选包**：便携版拿 -portable.zip（默认直连），安装版拿 -standard.zip（保留默认代理 127.0.0.1:7897）。两份包只差默认代理和 portable.flag，拿错了会改掉对方的默认设置。
3. **选通道**：对「直连 + ghproxy.net + gh-proxy.com + ghfast.top」各拉 256KB 测速，挑最快的下载；界面显示每个通道的实测速度。
4. **校验**：用 Release 资产自带的 sha256 digest 校验，不一致直接删文件并报错；下载中 45 秒无数据触发看门狗。
5. **覆盖**：写批处理，等本进程退出后 robocopy 覆盖，跳过 data、results、userData、logs、portable.flag（已有 runtime/ 时也跳过运行时，避免撞上正在运行的 electron.exe），然后自动重启。

实测：安装版 1.1.4 → 1.1.5 走标准包，默认代理保留、125 条去重记录与 42 个结果文件全部保留、软件自动重启。
